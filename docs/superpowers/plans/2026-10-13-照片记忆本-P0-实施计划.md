# 照片记忆本 P0：批量导入与长期副本自动收录实施计划

> **执行要求：**实施本计划时必须使用 `superpowers:executing-plans`，严格按任务顺序推进，并使用测试驱动开发。所有步骤使用复选框跟踪。

**目标：**完成可靠的单张与批量照片导入，实现标题和心情持久化、由用户授权的主题自动收录长期副本，并同步更新 PRD 与前后端技术方案 Word 文档。

**架构：**PostgreSQL 保存记忆字段和主题/长期副本规则；NestJS 作为数据校验和长期副本关联的唯一业务来源；React 负责用户授权弹窗和顺序执行、允许部分成功的上传队列，继续复用现有媒体与记忆接口。

**技术栈：**React、TypeScript、Vite、Vitest、NestJS、Prisma、PostgreSQL 18、浏览器原生文件选择、现有 EXIF 解析器、python-docx 与文档渲染工具。

**对应设计规范：**`docs/superpowers/specs/2026-10-12-photo-memory-p0-import-auto-copy-design.md`

## 一、全局约束

- 所有项目代码和生成文档必须保存在 `D:\yxy5.0`，不得把项目代码复制到 C 盘。
- 一条记忆对应一张照片，允许重复导入相同图片。
- 优先使用照片 EXIF 拍摄时间；没有 EXIF 时使用导入时间。
- 标题、备忘录、心情、状态、主题均为可选字段。
- 不存在“待补充记忆”状态、入口或角标。
- “无”主题永远不触发长期副本提示，也不能关联长期副本。
- 同一个用户的同一个主题最多关联一个长期副本。
- 批量导入继续使用现有单文件接口；单张失败不得回滚已经成功的照片。
- 数据库迁移必须保留已有 PostgreSQL 数据；旧记忆的标题和心情默认为空字符串。
- 当前目录不是 Git 仓库，不初始化 Git；每项任务使用测试结果作为检查点。

## 二、重点审查风险

- 在编辑记忆时异步创建自定义主题，主题返回后必须立即选中，不能要求用户再次点击。
- 把记忆主题从 A 改为 B 时，必须在同一事务中删除 A 的副本关联，并添加符合规则的 B 副本关联。
- 批量导入开始前，如果主题或长期副本规则保存失败，不得开始上传；开始后某一张失败不得阻止后续照片。
- 记忆超过 50 条后，刷新页面必须通过游标分页完整读取，不能重复或无限循环。
- 暂停、完成、归档或关闭自动收录的副本不得接收新记忆。
