# 照片记忆本 P0：批量导入、主题自动收录与标题修复设计规范

日期：2026-10-12  
项目目录：`D:\yxy5.0`  
状态：设计已在对话中逐节确认，等待书面规范审阅

## 1. 背景与目标

照片记忆本采用“先保存照片，之后再补充文字”的产品理念。当前版本已经具备单张照片、备忘录、状态、主题和长期副本能力，但存在以下问题：

1. 记忆标题只存在于前端对象中，没有传入后端，也没有数据库字段，编辑后无法持久化和回显。
2. 心情被前端混入状态数组，后端没有独立心情字段，重新加载后无法还原心情。
3. 自定义主题创建后没有自动选中，主题与长期副本之间缺少明确的自动收录授权。
4. 后端会把所有具有相同主题的记忆自动加入进行中的长期副本，没有按主题记录用户授权。
5. 上传入口仅支持单张图片，无法批量导入并处理部分失败。
6. “待补充记忆”不符合最新产品边界，需要彻底移除。

本次版本目标是建立完整且可测试的 P0 闭环：

> 导入一张或多张照片 → 选择或创建主题 → 用户决定长期副本授权 → 保存记忆 → 后端依据持久化规则自动收录 → 后续可逐张编辑。

## 2. 范围

### 2.1 本次实现

- 单张与批量照片导入。
- EXIF 拍摄时间优先、导入时间兜底。
- 批量照片统一设置一个相同主题。
- 批量导入进度、部分成功、失败原因与单项重试。
- 标题端到端持久化与展示。
- 心情独立持久化。
- 自定义主题创建后立即同步并自动选中。
- 主题级长期副本询问偏好。
- 长期副本自动收录开关。
- 一个弹窗集中处理一条记忆选择的多个主题。
- 长期副本关联随记忆主题变化同步更新。
- 搜索标题、备忘录、心情、状态和主题。
- 移除“待补充记忆”状态、角标、入口和判断逻辑。
- 更新产品需求文档与前后端技术方案 Word 文档。

### 2.2 本次不实现

- 月度总结、年度总结和“那年今日”的生成界面。
- AI 标题、AI 文案或自动识别照片内容。
- 图片去重；重复导入同一文件被允许。
- 多人共同编辑、账号体系或云端同步。
- 后端单请求批量上传接口。

## 3. 核心业务规则

### 3.1 记忆字段

每条记忆包含：

- 一张照片；
- 发生时间；
- 标题，可为空；
- 备忘录，可为空；
- 一个心情，可为空；
- 多个状态，可为空；
- 多个主题，可为空；
- 创建时间和修改时间。

标题、主题、状态、心情和备忘录不要求全部填写。所有成功保存的照片都直接进入“所有记忆”，不存在“待补充”分类或标记。

### 3.2 长期副本自动收录

- “无”主题不触发长期副本提示，也不允许创建长期副本。
- 一个普通主题最多关联一个长期副本，避免一张照片重复流入同主题的多个副本。
- 长期副本具有 `autoCollectEnabled` 开关。
- 从长期副本页面手动创建时，该开关默认开启，用户可关闭。
- 只有状态为“进行中”且自动收录开启的长期副本接收新的同主题记忆。
- 暂停、完成、归档的长期副本不自动接收新记忆；恢复为进行中后继续依据开关收录。
- 用户选择主题时：
  - 已存在符合自动收录条件的长期副本：无需提示，后端自动关联。
  - 存在长期副本但自动收录关闭：提示是否把当前照片加入并开启后续自动收录。
  - 不存在长期副本：提示是否创建同名长期副本并开启自动收录。
- 普通拒绝只跳过本次，下次选择同主题时继续询问。
- 用户勾选“以后不再询问此主题”后，持久化主题级抑制设置；以后不再自动弹窗，但仍可从长期副本页面手动创建。
- 一张照片同时选择多个需要询问的主题时，在一个弹窗中列出所有主题，用户逐项决定。

### 3.3 编辑后的关联同步

保存或编辑记忆后，后端重新计算长期副本关联：

- 对当前主题中满足自动收录规则的副本创建关联。
- 对已从记忆中移除的主题，删除对应长期副本关联。
- 用户确认创建或启用长期副本时，“加入当前照片”和“开启以后自动收录”作为同一个动作；本次不提供“只加入当前照片”的独立选项。
- 用户拒绝时，当前照片不关联该主题的长期副本；普通拒绝不改变以后再次询问的规则。
- 后端以唯一关联约束保证重复保存不会产生重复节点。

## 4. 数据模型设计

### 4.1 Memory

新增：

- `title String @default("")`
- `mood String @default("")`

移除：

- `isPending`

保留：

- `statuses String[]`
- `topics MemoryTopic[]`

旧数据迁移时标题和心情使用空字符串，不影响既有照片、备忘录、状态、主题与长期副本关联。

### 4.2 Topic

新增：

- `suppressLongTermPrompt Boolean @default(false)`

该字段仅表示是否抑制系统主动询问，不影响用户手动创建长期副本。

### 4.3 LongTermCopy

新增：

- `autoCollectEnabled Boolean @default(true)`

约束：

- 同一用户与主题只允许一个长期副本。MVP 中归档后仍保留该唯一关系；用户如需继续记录，应重新启用原副本，而不是创建第二个同主题副本。

### 4.4 数据库迁移

新增迁移文件，不修改已有 `0001_init`：

- 为 `Memory` 增加 `title`、`mood`。
- 删除 `Memory.isPending`。
- 为 `Topic` 增加 `suppressLongTermPrompt`。
- 为 `LongTermCopy` 增加 `autoCollectEnabled`。
- 为 `LongTermCopy(userId, topicId)` 建立唯一索引。

迁移必须兼容已有本地 PostgreSQL 数据。

## 5. 后端设计

### 5.1 记忆接口

`POST /api/memories` 与 `PATCH /api/memories/:id` 支持：

- `title`
- `note`
- `mood`
- `statuses`
- `topics`

返回模型同步包含以上字段。后端负责：

- 校验图片和主题归属当前用户。
- 去重状态与主题 ID。
- 保存或更新记忆。
- 按当前主题及长期副本规则同步关联。
- 编辑主题时删除已经不再适用的长期副本关联。

搜索接口把 `title`、`note`、`mood`、`statuses` 和主题名称纳入关键词匹配。

### 5.2 主题接口

主题创建接口返回完整主题对象。新增更新能力用于保存 `suppressLongTermPrompt`。创建同名主题时，前端可把冲突响应解释为“使用已有主题”，但后端仍保持唯一约束。

### 5.3 长期副本接口

创建和更新接口支持 `autoCollectEnabled`。创建时检查同一用户是否已有相同主题副本；存在时返回明确冲突信息，不产生重复记录。

前端在记忆保存前完成主题决策：

- 需要创建副本时，先调用长期副本创建接口。
- 需要启用现有副本时，先更新自动收录开关并确保状态为进行中。
- 需要永久抑制提示时，更新主题设置。
- 规则保存成功后，再提交记忆。

如果副本规则保存失败，记忆编辑表单保留用户输入且不继续保存，防止界面显示的授权与数据库不一致。

### 5.4 分页

前端记忆仓储连续请求 `nextCursor`，直到完整读取所有页面，解决当前只显示前 50 条记忆的问题。批量导入完成后无需依赖重新加载全部数据，但刷新页面仍能读取完整记录。

## 6. 前端设计

### 6.1 单张编辑

- 文件选择框支持一张或多张图片。
- 选择一张时进入现有记忆编辑表单。
- 自定义主题创建方法返回创建后的主题对象；表单收到后立即选中新主题。
- 点击保存时先计算需要提示的主题，再打开统一确认弹窗。
- 用户完成决策后保存主题策略，再保存记忆。
- 标题、心情、状态和主题在重新打开页面后正确回显。

### 6.2 批量导入

- 选择两张及以上图片时进入批量导入流程。
- 首先询问是否设置相同主题。
- 选择“否”时直接进入导入确认，不设置任何主题。
- 选择“是”时允许从已有普通主题中选择一个，或现场创建一个并自动选中。
- 在开始上传前处理一次长期副本确认，避免每张图片重复弹窗。
- 每张照片独立执行：读取时间 → 上传媒体 → 创建记忆。
- 每条批量记忆只保存照片、时间和可选的统一主题；标题、备忘录、心情、状态为空。
- 同一批次按顺序处理，界面实时显示成功、失败和总数。
- 失败项保留 `File` 引用、文件名和错误消息，可逐项重试。
- 用户关闭已结束的进度弹窗后，成功照片仍保留在当前页面。
- 重复图片不做去重。

### 6.3 主题与长期副本确认弹窗

弹窗输入为所选主题中尚未自动收录且未被永久抑制的项目。每个主题可选择：

- 创建或启用长期副本并自动收录；
- 本次不创建；
- 本次不创建且以后不再询问。

多个主题在同一个弹窗中逐项展示。所有主题都作出决定后才能继续保存。

### 6.4 展示与搜索

- 记忆卡片显示标题；标题为空时使用中性占位文案。
- 详情页、普通时间线、长期副本时间线显示标题。
- 标签区域分别显示心情、状态和主题。
- 搜索匹配标题、备忘录、心情、状态和主题名称。
- 删除所有 `pending-badge`、`pending-inline` 和 `isPendingMemory` 使用点。

## 7. 状态与组件边界

建议新增或拆分以下前端单元：

- `BatchImportDialog`：主题选择、批量任务状态和结果展示。
- `LongTermCopyDecisionDialog`：集中处理主题授权。
- `batch-import.ts`：纯业务函数，建立任务并逐项执行，便于测试。
- `long-term-copy-policy.ts`：计算哪些主题需要提示、哪些主题已自动收录。

`App` 负责仓储实例、全局数据刷新和打开弹窗，不直接承载批量循环与规则判断。

后端继续按 `memories`、`topics`、`long-term-copies` 模块分工；长期副本关联同步封装为记忆服务内部的独立方法，所有创建和编辑入口复用。

## 8. 错误处理

- 非图片文件在上传前拒绝并显示文件名。
- 创建主题失败时保留表单内容。
- 创建或启用长期副本失败时不提交记忆。
- 批量任务中一张图片失败不终止后续图片。
- 失败项可重试，已成功项不重复提交。
- 接口返回重复长期副本冲突时刷新长期副本列表，并提示用户使用现有副本。
- 网络中断时显示实际错误，不把失败项标记为成功。
- 后端事务保证单条记忆及其主题、长期副本关联同步提交。

## 11. 验收标准

1. 单张照片可保存完整字段，刷新页面后标题、心情、状态、主题和备忘录不丢失。
2. 新建主题立即出现在记忆和长期副本中，并自动选中当前记忆。
3. 首次选择未关联主题时出现确认；同意后创建或启用副本，后续同主题照片自动收录。
4. 普通拒绝后下次继续询问；选择以后不再询问后不再弹出。
5. 多主题只出现一个集中确认弹窗。
6. 手动创建长期副本可控制自动收录，默认开启。
7. 批量导入可选择不设主题或统一主题；统一主题只询问一次长期副本规则。
8. 批量导入显示进度，部分失败不影响其他图片，失败项可重试。
9. 所有导入照片直接进入所有记忆，不出现待补充状态或标签。
10. 编辑移除主题后，照片不再出现在该主题长期副本中。
11. 重复图片允许再次导入。
12. 所有测试、类型检查和构建通过后才视为完成。
