## 1. 背景与目标

照片记忆本已经建立“先保存照片、之后补充文字”的记录闭环，并具备标题、备忘录、心情、状态、主题、长期副本、批量导入以及月度/年度总结等能力。本次版本进一步强化产品的情感价值与用户的数据掌控感，新增两个核心子系统：

1. **记忆回声**：在合适的时间重新呈现具有纪念意义的旧记忆，让用户看到“那时的自己”和长期主题的变化。
2. **数据保险箱**：提供数据导出、数据库备份状态、导入恢复、应用锁和存储位置说明，降低长期记录的数据焦虑。

本次版本的产品目标是：

> 用户当天首次打开首页时，系统从历史照片记忆中生成最多三条稳定、可解释、可控制的记忆回声；用户可写下独立的回声感言。同时，用户可以随时导出、备份和恢复自己的照片与文字，并清楚知道数据保存在哪里。

## 3. 记忆回声业务规则

### 3.1 生成时机与稳定性

- 使用用户时区 `Asia/Shanghai` 计算自然日。
- 用户当天首次打开首页并请求回声时，后端检查当天是否已经存在回声快照。
- 若已存在，直接返回同一批快照；若不存在，执行一次生成并持久化。
- 同一天刷新页面、重启前端或重复请求不会重新抽取。
- “换一条”只在当天已生成的最多三条回声中轮换，不触发重新生成。
- 回声生成失败不阻断首页其他数据加载，用户可单独重试。

### 3.2 候选记忆条件

记忆进入候选池必须同时满足：

- 未被软删除。
- 发生时间距当前日期至少三十天。
- 记忆没有被用户永久排除在回声之外。
- 所属主题没有关闭回声。
- 心情没有被用户加入排除列表。
- 最近三十天没有作为正式回声展示。

若没有符合条件的记忆，返回空状态；不为凑足三条而降低基本质量门槛。

### 3.3 回声类型与评分

| 回声类型 | 基础分 | 说明 |
| --- | ---: | --- |
| 往年今日 | 100 | 月日相同且发生于往年 |
| 长期副本周年节点 | 95 | 一周年及后续整年周年 |
| 长期副本阶段里程碑 | 90 | 30 天、100 天、365 天等节点 |
| 长期副本第一段记忆 | 80 | 某个长期主题的起点 |
| 过去与现在 | 75 | 长期副本的第一段与近期记忆形成对照 |
| 普通主题旧记忆 | 50 | 在高优先级内容不足时提供温和回顾 |

补充排序规则：

- 同一记忆命中多个类型时只保留得分最高的类型。
- 相同分数优先选择更久远、信息较完整的记忆。
- 每天尽量选择不同主题；若同主题候选过多，对重复主题施加降权。
- 最终按得分和稳定的次级排序选出最多三条。
- 每条回声必须保存清晰、可解释的推荐原因。

### 3.4 展示内容与用户动作

每张回声卡片展示：

- 原照片。
- 事件标题。
- 原始发生时间。
- 回声原因。
- 备忘录、心情、状态和主题。
- 打开原始记忆入口。
- 写下或编辑回声感言入口。
- 换一条、暂时跳过、不再推荐、关闭主题回声入口。

“暂时跳过”只影响当天该条快照；“以后不再推荐这段记忆”永久排除原记忆；“关闭该主题的回声”会更新主题设置，但不影响主题本身、长期副本或总结功能。

### 3.5 回声感言

- 回声感言是用户看到旧记忆之后写下的新感受。
- 独立于原始记忆备忘录，不创建新照片记忆，也不修改原始内容。
- 同一条原始记忆允许在不同日期产生多条感言，每条感言关联来源回声日期。
- 支持保存后再次编辑，正文上限为 2000 字。
- 回声页面只展示最近三十天的回声快照；已经保存的感言长期保留，并可在原始记忆详情中查看。

## 6. 回声后端设计

### 6.1 接口

- `GET /api/echoes/today`：读取当天快照；不存在时生成一次。
- `GET /api/echoes?days=30`：读取最近三十天回声。
- `PUT /api/echoes/:id/reflection`：新增或更新该来源回声的感言。
- `POST /api/echoes/:id/dismiss`：暂时跳过当天快照。
- `PATCH /api/memories/:id/echo-setting`：排除或恢复单条记忆。
- `PATCH /api/topics/:id/echo-setting`：关闭或重新开启主题回声。
- `GET /api/echo-preferences`：读取回声偏好。
- `PATCH /api/echo-preferences`：更新总开关与排除心情。

### 6.2 当天生成流程

1. 计算上海时区当前自然日。
2. 查询该用户当天回声快照。
3. 已存在则直接返回。
4. 不存在则读取偏好、可用记忆、主题和长期副本。
5. 执行候选过滤和最近三十天去重。
6. 计算回声类型、理由与得分。
7. 进行主题多样性处理并选出最多三条。
8. 在事务中创建回声快照。
9. 并发请求触发唯一约束时，重新读取已生成快照并返回。

领域规则应封装为纯函数，数据库服务负责查询、事务和持久化，便于覆盖评分、里程碑和时区边界测试。

### 7.1 数据保险箱页面

### 7.2 导出格式

#### JSON

- 保存完整结构化业务数据和导出元信息。
- 不把照片二进制直接嵌入 JSON。
- 包含数据格式版本，供兼容性校验。

#### PDF

- 生成人可阅读的图文记忆册。
- 包含照片缩略图、标题、时间、备忘录、心情、状态、主题、长期副本和回声感言。
- PDF 以阅读与保存为目标，不作为完整恢复源。

#### ZIP

- 作为主要完整迁移包。
- 包含原始照片、`data.json`、`manifest.json`、校验值和导出时间。
- 文件路径采用包内相对路径，避免把本机绝对路径泄露到迁移包。
- 临时文件先写入项目临时目录，成功后原子移动到导出目录；失败时清理半成品。

### 7.3 导入恢复

导入分为三个阶段：

1. **校验**：检查格式版本、清单、照片数量、文件大小、哈希和必填关系。
2. **预览**：展示新增、重复、冲突、缺失和异常数据数量。
3. **确认恢复**：用户确认并通过应用锁二次验证后执行。

默认采用安全合并：

- 使用来源记录 ID 和照片内容哈希去重。
- 不直接覆盖当前记录。
- 同 ID 但内容不同的记录创建“导入副本”，同时生成新的本地 ID 并重建关系。
- 导入前自动创建安全备份。
- 数据库写入使用事务；照片先进入隔离临时目录，事务成功后移动到正式目录。
- 任一步失败时回滚数据库、清理临时照片，不留下半完成状态。

### 7.4 数据库备份状态

页面显示：

- PostgreSQL 连接是否正常。
- 主机、端口、数据库名和 schema；密码始终隐藏。
- 最近一次备份时间、状态、文件大小、校验值和保存位置。
- 最近一次恢复时间和状态。
- “立即备份”和“打开备份目录”入口。

MVP 使用手动触发的本地备份，不实现后台定时任务。后端通过受控的 PostgreSQL `pg_dump` 流程生成备份，并将状态记录到数据库；命令参数不得出现在前端或普通日志中。

### 7.5 存储目录

项目运行产生的数据统一位于 `D:\yxy5.0`：

- 原始照片：`D:\yxy5.0\data\uploads`
- 数据库备份：`D:\yxy5.0\data\backups`
- 用户导出：`D:\yxy5.0\data\exports`
- 临时导入/导出：`D:\yxy5.0\data\temp`

数据库使用本机 PostgreSQL，应用展示主机、端口、数据库名与 schema，但隐藏用户名中的敏感部分和全部密码。项目源代码、照片、备份和导出文件不保存到 C 盘；操作系统、浏览器或包管理器自身缓存不属于项目数据范围。

## 8. 应用锁

### 8.1 能力范围

- 本地单用户 Web MVP 使用独立访问密码，不引入完整账户系统。
- 用户主动首次设置密码，之后访问受保护页面时需要解锁。
- 默认无操作三十分钟后自动锁定，支持手动立即锁定。
- 支持修改密码、关闭应用锁和调整自动锁定时间。
- 导出、导入恢复、查看或打开备份位置等敏感操作必须二次验证。

### 8.2 安全实现

- 后端使用安全密码派生算法保存带盐摘要，不保存明文密码。
- 登录成功后发放短期服务器会话，使用 `HttpOnly`、`SameSite=Strict` Cookie。
- 连续失败达到阈值后短暂限制重试，并记录不含密码的安全事件。
- 恢复密钥在设置应用锁时生成并仅完整显示一次；数据库仅保存恢复密钥摘要。
- 忘记密码时通过恢复密钥重置，不通过安全问题找回。
- 密码、摘要、恢复密钥、会话、数据库连接密码不得进入导出包、Git 仓库或普通日志。

## 10. 错误处理与一致性

- 回声模块失败时不影响记忆列表、长期副本和总结功能。
- 当天快照依赖数据库唯一约束和事务保证幂等。
- 回声感言保存失败时保留输入并允许重试。
- 导入包中的未知字段忽略，必填字段或关系损坏则阻止恢复。
- 导入文件必须限制类型、单文件大小、总大小和条目数量。
- 解压前检查路径，拒绝绝对路径和 `..` 路径，防止 ZIP Slip。
- 备份、导出和恢复写入独立状态记录，前端可读取真实结果。
- 所有敏感操作失败时返回可理解的错误，但不回显连接串、密码、命令行参数或服务器堆栈。
